## 1. Главная страница (публичная)

### Содержимое
- Заголовок: «Марафоны по здоровому питанию»
- Подзаголовок: описание платформы (2-3 строки)
- Список потоков (status = `open`):
    - Карточка:
        - Название марафона
        - Ментор (имя)
        - Дата начала
        - Длительность (дней)
        - Количество участников
        - Кнопка «Подробнее»
- Кнопки «Вход» / «Регистрация» (в шапке)

### Переходы
- Карточка → страница потока
- «Вход» → форма входа
- «Регистрация» → форма регистрации

## 2. Страница потока (публичная)

### Содержимое
- Название марафона
- Описание (из шаблона)
- Ментор (имя)
- Дата начала
- Длительность
- Количество участников (текущее)
- Кнопка:
    - «Записаться» (если не авторизован → перенаправление на вход)
    - «Вы записаны» (если уже записан)
    - «Набор завершён» (если start_date прошла)

### Переходы
- «Записаться» → подтверждение → «Мои марафоны»
- Ментор → профиль ментора (список его потоков)

---

## 3. Форма регистрации

### Поля
- Email (email, обязательно)
- Пароль (password, обязательно, минимум 8 символов)
- Подтверждение пароля (password, обязательно)
- Имя (text, обязательно)
- Роль (radio): «Участник» / «Ментор»
- Часовой пояс (select, список IANA, обязательно, дефолт — Europe/Moscow)
- Чекбокс «Я ознакомлен(а) с политикой обработки персональных данных» (обязательный, ссылка на `/privacy#policy`)
- Чекбокс «Я даю согласие на обработку персональных данных» (обязательный, ссылка на `/privacy#consent`)
- Кнопка «Зарегистрироваться» (неактивна, пока не отмечены оба чекбокса)

### Переходы
- Успешно → автоматический вход → страница по роли (участник → `/onboarding`)
- «Уже есть аккаунт?» → форма входа

## 5. Страница «Мои марафоны» (участник)

### Содержимое
- Заголовок: «Мои марафоны»
- Табы / фильтры:
    - «Текущие» (потоки status = running, где записан)

    - Дата начала
    - Статус (бегущий / завершён)
    - Прогресс: заполненные дни / всего дней
    - Кнопка «Продолжить» (для running) / «Результаты» (для finished)

### Переходы
- «Продолжить» → календарь дней марафона
- «Результаты» → страница результатов
- «Записаться на новый» → главная страница

## 6. Календарь дней марафона (участник)

### Содержимое
- Заголовок: название марафона, дата начала
- Сетка дней (1..N):
    - Каждый день — квадрат/карточка:
        - Номер дня
        - Иконка статуса: пустой / заполнен (галочка) / недоступен (замок)
    - Цвета:
        - Зелёный — заполнен
        - Белый/серый — доступен, не заполнен
        - Тёмный/заблокирован — будущий день
- Текущий день выделен рамкой

### Переходы
- Клик по доступному дню → страница дня
- Клик по недоступному — ничего / тултип «День откроется позже»
- Кнопка «Рейтинг» → рейтинг потока

## 7. Страница дня марафона (участник)

### Содержимое
- Назад → календарь
- Заголовок: «День X» / «Марафон: Название»
- Блок материалов (если есть):
    - Комплекты «PDF + аудио»: карточка с аудиоплеером и кнопкой «Открыть PDF в новой вкладке»
    - Текст (HTML из Quill) и/или PDF-документы под текстом
    - Аудио (список HTML5 audio player)
    - Видео (список embed Kinescope)
    - Если материалов нет — сообщение «Материалы для этого дня не добавлены»
- Блок отчёта:
    - Левая колонка (сайдбар): итоги дня и метрики, ширина колонки общая
        - Итоги дня: «Норма / дефицит», цель и факт по ккал, кольцевой дашборд пропорций БЖУ (белки/жиры/углеводы в % и граммах)
        - Карточка «Метрики» под итогами: вода (л), шаги, сон (ч), тренировка — ежедневно; вес и охваты — только в день замера (отдельной секцией внутри той же карточки)
    - Правая колонка: форма добавления продуктов и таблицы
        - Форма добавления: селектор приёма (Завтрак / Обед / Ужин / Перекус, по умолчанию — по времени суток) + один поиск продукта
        - Таблицы по приёмам (сгруппированы, в каждом подытог ккал и БЖУ):
            - Столбцы: Продукт (с ккал и БЖУ на 100 г) | Вес (г) | ккал | Б | Ж | У | Действия
            - Кнопка «Удалить» на каждой строке
    - Добавление продукта, которого нет в каталоге: форма с названием, ккал и обязательными Б/Ж/У (ккал подставляется из БЖУ, можно поправить)
    - Кнопка «Сохранить отчёт»
    - На мобильном (≤640px) колонки складываются в порядке «итоги → таблица → метрики»
- Сообщение об успешном сохранении

### Переходы
- «Сохранить» → обновление страницы / галочка в календаре
- «Назад» → календарь дней

## 12. Форма создания шаблона (ментор)

### Шаг 1: Основная информация
- Название (text, обязательно)
- Описание (textarea, обязательно)
- Длительность, дней (number, 1-90, обязательно)
- Кнопка «Далее — предстартовая страница»

### Шаг 2: Предстартовая страница
- Приветственный текст (Quill-редактор, опционально)
- Аудио: загрузка нескольких файлов (опционально)
- Видео: ссылки Kinescope (опционально)
- PDF-документы (опционально)
- Кнопка «Сохранить и перейти к дням» / «Пропустить»

### Шаг 3: Дни марафона
- Список дней (1..N):
    - Каждый день — карточка/вкладка:
        - «День X»
        - День замера (вес и охваты)
        - Текст: Quill-редактор (опционально)
        - Комплект «PDF + аудио»: выбор PDF и аудиофайла одним действием
        - PDF: загрузка одного или нескольких PDF (отображаются под текстом)
        - Аудио: загрузка нескольких файлов (опционально)
        - Видео: ссылки Kinescope (опционально)
        - Предпросмотр материалов
- Кнопка «Сохранить черновик»
- Кнопка «Отправить на проверку» (все дни созданы)

### Переходы
- «Сохранить черновик» → список шаблонов (status = draft)
- «Отправить на проверку» → список шаблонов (status = pending_review)

## 17. Правила и помощь (публичный раздел)

### Список — `/help`
- Заголовок «Правила и помощь», короткое описание
- Поиск по заголовку и краткому описанию (с задержкой ввода)
- Табы: «Все», «Правила», «Инструкции», «Частые вопросы», «Персональные данные»
- «Персональные данные» — статичная вкладка (не из CMS): рендерит общий компонент
  `src/components/legal/PrivacyDocuments.tsx` (тот же, что и `/privacy`), поиск скрыт
- Карточки статей: бейдж раздела, бейдж аудитории, заголовок → статья, краткое описание, дата обновления
- Гость видит только общие статьи; участник/ментор — плюс статьи своей роли; админ — все
- Для админа — кнопка «Управление разделом» → `/admin/help`

### Статья — `/help/[slug]`
- Ссылка «← К правилам и помощи»
- Бейджи раздела и аудитории, заголовок, краткое описание
- Санированный HTML (Quill), дата обновления
- Блок «Другие материалы раздела» — до 4 карточек того же раздела

### Управление (админ) — `/admin/help`
- Таблица: заголовок + slug, раздел, аудитория, порядок, статус (опубликована/черновик), действия
- «Добавить статью» → `/admin/help/new`; «Изменить» → `/admin/help/[slug]`
- Форма статьи: заголовок, slug (автоподстановка из заголовка), раздел, аудитория, порядок, краткое описание, текст в визуальном редакторе, чекбокс «Опубликовать»
- Удаление с подтверждением

### Контекстные ссылки
- День марафона, блок «Отчёт» → «Как заполнить отчёт?»
- Публичная страница потока → «Правила марафона»
- Форма регистрации → «правилами марафона»

## 18. Админ-панель: Каталог продуктов — `/admin/products`

### Список
- Заголовок «Каталог продуктов», пояснение про ккал и БЖУ на 100 г
- Поиск по названию + сброс, пагинация
- Таблица: Название | ккал/100г | Б | Ж | У | действия
- Кнопки «Редактировать» (`/admin/products/[id]`) и «Удалить» (с подтверждением)
- «Добавить продукт» → `/admin/products/new`

### Формы создания/правки
- Название, ккал/100г, Белки/Жиры/Углеводы (г/100г)
- Ккал авто-подставляется из БЖУ (`4×Б + 9×Ж + 4×У`), но остаётся редактируемой
- Валидация: Б/Ж/У — от 0 до 100, сумма не больше 100
- Удаление продукта, уже использованного в отчётах, запрещено (сообщение об ошибке)

## 19. Отчёт участника (ментор) — `/mentor/streams/[id]/participants/[participantId]`

### Содержимое
- Ссылка «← Назад к потоку»
- Имя и email участника, название марафона, «день X из N»
- Кнопка «Написать участнику» → чат потока с выбранным участником
- Сводка: место в рейтинге и потеря веса, заполнено дней, средние калории, последнее обновление,
  дата начала, статус
- Вкладки отчёта (подчёркнутые, состояние локальное, по умолчанию открыт «Рацион»):
    - **Рацион** — таблица по всем дням: День | Состав | Итого ккал
        - строки с данными раскрываются и сворачиваются по клику (стрелка поворачивается на 90°);
          в раскрытом виде — состав по приёмам с весом, ккал и БЖУ
        - дни без данных не раскрываются
    - **Метрики** — таблица по всем дням: вода, шаги, сон, тренировка, вес и охваты
    - **Графики** — линейный график «Динамика замеров»: вес, ОГ, ОТ, ОБ, ОН по дням замера
- Блок «Пульс и давление» с этой страницы убран: данные не показываем, пока не решено, что с ними
  делать (API их по-прежнему возвращает)

### Переходы
- «Назад к потоку» → страница потока
- «Написать участнику» → чат потока

## 20. Персональные данные (публичная) — `/privacy`

Единая публичная страница: политика обработки ПДн и два текста согласий отдельными
блоками с якорями.

### Содержимое
- Плашка «Черновик» с текущей версией текста (`POLICY_VERSION` из `src/lib/consent.ts`)
- Навигация по якорям: `#policy`, `#consent`, `#consent-health`
- Блок «Политика обработки персональных данных» (цели, категории данных, основания,
  сроки, передача, права субъекта, контакты)
- Блок «Согласие на обработку персональных данных» (`#consent`)
- Блок «Согласие на обработку данных о здоровье» (`#consent-health`)

### Особенности
- Доступна без авторизации; ссылка — вкладкой «Персональные данные» в разделе
  «Правила и помощь» (`/help`), а также на регистрации и в анкете участника.
  Отдельного пункта в шапке нет.
- Тексты — общий компонент `src/components/legal/PrivacyDocuments.tsx`
  (используется и вкладкой `/help`, и страницей `/privacy`; якори работают в обоих местах).
- **Тексты — заглушки** (помечены `[Заполнит юрист]`), структура размечена. После правок
  меняется версия в `src/lib/consent.ts`, и согласие перезапрашивается.
- Оформление — CSS Module (`PrivacyDocuments.module.css`) на токенах; комментарий про
  здоровье выделен `--bg-warning`.

## 21. Аккаунт и данные (авторизованные) — `/account`

Раздел прав субъекта ПДн (152-ФЗ). Ссылка «Аккаунт» в шапке для всех ролей.

### Содержимое (компонент `src/components/account/AccountDataSection.tsx`)
- **Согласия**: по каждому виду (`general`, `health`) — ссылка на текст, версия, дата выдачи,
  статус «действует / не действует» и кнопка «Отозвать» для активного согласия.
- **Экспорт данных**: описание и кнопка «Скачать мои данные» — скачивает JSON-файл.
- **Удаление аккаунта**: предупреждение, поля «Пароль» и подтверждение словом «удалить»,
  кнопка danger. Для ментора над формой — красная плашка с числами из
  `GET /api/users/me/deletion-impact`: сколько шаблонов, потоков, записей и участников
  будет затронуто (каскад удаляет данные участников). Для админа формы нет — пояснение,
  что служебный аккаунт не удаляется.

### Переходы
- После удаления аккаунта — выход и редирект на главную (`/`).
- Неавторизованный → `/login`.

Визуальный язык зафиксирован отдельно — см. **`DOC/style-guide.md`** (палитра с контрастами, типографика,
компоненты со состояниями, брейкпоинты, правила). Ниже — только краткая выжимка.

- **Адаптивность**: веб, обязательный адаптив под мобильные (участники заполняют отчёты с телефона).
  Брейкпоинты: `≤640` мобильный, `≤900` планшет (на нём хедер сворачивается в бургер), `>900` десктоп.
- **Цветовая схема**: молочные нейтрали, графитовый текст, один мятный акцент, клейморфизм (мягкие
  тени у «поднятых» поверхностей, «вдавленные» поля). На мятных заливках и панелях текст только тёмный —
  белый там не проходит по контрасту; для текста и ссылок есть отдельный токен `--accent-strong`.
- **Хедер**: светлая плашка, слева текстовое название «Marathon Platform». Логотип-картинка в интерфейсе не используется.
- **Шрифт**: Onest (кириллица), подключается через `next/font`.
- **Регистр**: всё в sentence case, `text-transform` не используем.
- **Фото/аватарки**: не требуются в MVP.
- **Иконки**: тонкие линейные, `lucide-react` (галочка, замок, плюс, удалить, поиск и т.д.).
