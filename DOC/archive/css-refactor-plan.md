# План систематизации стилей

> Цель: сохранить текущую простую визуальную эстетику, но убрать дублирование и сделать стили поддерживаемыми.
> Принцип: глобальные стили (design tokens + utility-классы) + собственные CSS Modules у компонентов, где это нужно.
> Ограничения: не добавляем Tailwind, styled-components и прочие фреймворки; не меняем бизнес-логику.

---

## Этап 1. Подготовка design tokens в `globals.css`

**Файлы:**
- `src/styles/globals.css`

**Задачи:**
1. Добавить CSS-переменные в `:root`:
   - цвета фона, поверхностей, текста, границ, акценты;
   - отступы;
   - радиусы скругления;
   - тени;
   - типографику (размеры шрифта, межстрочное расстояние);
   - контейнеры (max-width, высота шапки).
2. Оставить существующий reset (`*`, `html`, `body`).
3. Обновить `body`, чтобы font-family использовалась через переменную (или оставить как есть, если шрифт один).
4. Не создавать пока utility-классы — только переменные.

**Критерий готовности:** в `globals.css` появился блок `:root` с переменными, которые отражают текущие значения из приложения. Сборка (`npm run build`) не ломается.

## Этап 2. Вынести `Layout` в CSS Module

**Файлы:**
- `src/components/Layout.tsx`
- `src/components/Layout.module.css` (новый)

**Задачи:**
1. Создать `Layout.module.css`.
2. Перенести туда стили для:
   - `.header`
   - `.container`
   - `.logo`
   - `.nav`
   - `.link`
   - `.button` (кнопка Logout в шапке)
   - `.main`
3. В `Layout.tsx` заменить `const xxxStyle: React.CSSProperties = {...}` и `style={xxxStyle}` на `className={styles.xxx}`.
4. Использовать CSS-переменные из `globals.css`.

**Критерий готовности:** `Layout.tsx` не содержит объектов стилей внутри файла, внешний вид шапки не изменился, сборка проходит.

## Этап 6. Глобальные utility-классы и рефактор страниц

**Файлы:**
- `src/styles/globals.css`
- страницы в `src/pages/**/*.tsx`

**Задачи:**
1. Добавить в `globals.css` utility-классы:
   - `.container` — `max-width: var(--container-width); margin: 2rem auto; padding: 0 1rem;`
   - `.containerNarrow` — узкий вариант для форм логина;
   - `.card` — стили карточки (граница, скругление, отступы);
   - `.btn` — базовая кнопка;
   - `.btnPrimary` / `.btnOutline` — если потребуется;
   - `.input` — базовый input;
   - `.error` — красный текст ошибки;
   - `.listPlain` — список без `list-style` и отступов;
   - `.pageTitle`, `.pageSubtitle` — типографика заголовков.
2. Заменить повторяющиеся inline-стили в страницах на utility-классы.
3. Начать с наиболее типовых страниц:
   - `login.tsx`
   - `register.tsx`
   - `index.tsx`
   - `dashboard/index.tsx`
   - `admin/index.tsx`
4. Более специфичные страницы (с формами шаблонов, потоков и т.д.) рефакторить после, если пользователь одобрит.

**Критерий готовности:** страницы выглядят как раньше, дублирование стилей сокращено, сборка проходит.

## Правила на каждом этапе

- Один этап = одна итерация, которую можно независимо проверить.
- Перед началом этапа можно уточнить детали; после этапа — обсудить результат.
- Не добавлять новые зависимости.
- Не менять логику компонентов и страниц.
- Сохранять текущий внешний вид: рефакторинг, а не редизайн.
