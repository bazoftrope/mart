# Административный рабочий процесс

## Роль администратора

Администратор — единственный модератор платформы в MVP. Его задача: проверять марафоны-шаблоны перед публикацией и давать разрешение на запуск.

**Принцип:** Админ не создаёт контент, не взаимодействует с участниками, не управляет потоками. Только модерация шаблонов.

---

## Вход в админ-панель

- Отдельный URL (например, `/admin`)
- Зашитые учётные данные (hardcoded в MVP, без интерфейса создания админов)
- Email и пароль задаются при развёртывании

---

## Процесс модерации

### 1. Ментор создаёт шаблон

```
Ментор
    ↓
Создание шаблона (название, описание, дни, материалы)
    ↓
Сохранение как черновик (status = draft)
    ↓
Редактирование по необходимости
    ↓
Кнопка «Отправить на проверку»
    ↓
Статус: pending_review
```

**Ограничения:**
- Ментор может редактировать шаблон пока статус `draft` или `pending_review`.
- После одобрения — редактирование невозможно (MVP).

---

### 2. Админ видит шаблон на проверке

```
Админ
    ↓
Вход в админ-панель
    ↓
Раздел «Марафоны на проверке»
    ↓
Список шаблонов (status = pending_review):
    - Название
    - Ментор (имя, email)
    - Дата отправки
    - Длительность (дней)
    - Кнопка «Просмотреть»
```

---

### 3. Админ проверяет шаблон

```
Клик «Просмотреть»
    ↓
Страница шаблона:
    - Название
    - Описание
    - Длительность
    - Дни (1..N):
        - День X
        - Текст (полный текст)
        - Аудио (ссылка/плеер)
        - Видео (ссылка/плеер)
        - Примечание: «Материалы отсутствуют» (если пусто)
    - Кнопка «Одобрить»
```

**Критерии проверки (не формализованы, на усмотрение админа):**
- Название и описание не пустые
- Длительность разумная (1-90 дней)
- Материалы не нарушают законодательство (нет спама, нет вредных советов)
- Контент соответствует теме здорового питания

---

### 4. Одобрение

```
Клик «Одобрить»
    ↓
Статус шаблона → approved
    ↓
Шаблон исчезает из списка «на проверке»
    ↓
Ментор получает возможность запускать потоки из этого шаблона
```

**После одобрения:**
- Шаблон виден только ментору (в его списке шаблонов)
- Потоки из шаблона публичны (после запуска ментором)

---

### 5. Отклонение / возврат на доработку (вне системы)

В MVP нет кнопки «Отклонить» и нет встроенной коммуникации.

**Процесс:**
```
Админ видит проблему в шаблоне
    ↓
Пишет ментору на email (вне платформы)
    ↓
Ментор заходит в шаблон (status = pending_review)
    ↓
Ментор редактирует по комментариям
    ↓
Ментор снова нажимает «Отправить на проверку» (или оставляет как есть)
    ↓
Админ проверяет снова
```

**Почему так:**
- MVP — минимум функций
- Поток марафонов на проверке в начале будет низким
- Email достаточен для коммуникации
- Встроенные комментарии — версия 2

---

## Статусы шаблона и переходы

```
┌─────────┐     ментор отправляет      ┌──────────────┐
│  draft  │ ─────────────────────────→ │ pending_review│
└─────────┘                            └──────────────┘
     ↑                                        │
     │ ментор снимает с проверки               │ админ одобряет
     │ (если нужно доработать)                  ↓
     │                                   ┌───────────┐
     └───────────────────────────────────│ approved  │
                                         └───────────┘
                                              │
                                              │ ментор запускает поток
                                              ↓
                                         ┌───────────┐
                                         │  потоки   │
                                         └───────────┘
```

## Админ-панель: структура

### Разделы (MVP)

| Раздел | Содержимое |
|--------|-----------|
| «Марафоны на проверке» | Список шаблонов `pending_review`, просмотр, одобрение |
| (в будущем) «Пользователи» | Список менторов и участников |
| (в будущем) «Продукты» | Управление базой продуктов |
| (в будущем) «Статистика» | Активность платформы |

**MVP — только «Марафоны на проверке».**

---

## Граничные случаи

| Ситуация | Решение |
|----------|---------|
| Ментор удалил шаблон на проверке | Шаблон удаляется из списка на проверке, админ не видит |
| Ментор редактирует шаблон на проверке | Админ видит актуальную версию при просмотре |
| Админ одобрил, ментор хочет изменить | Невозможно в MVP. Ментор создаёт новый шаблон. |
| Два админа одновременно проверяют один шаблон | Последний одобривший «побеждает», статус `approved`. Редкий случай, не обрабатываем в MVP. |
