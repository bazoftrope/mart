# План расширения отчёта участника

## Цель

Добавить в ежедневный отчёт участника марафона возможность сохранять:

- количество выпитой воды;
- количество пройденных шагов;
- длительность сна;
- замеры пульса (время + значение, возможно несколько за день);
- активность/тренировку в минутах;
- вес.

**Границы задачи:** собираем данные и обеспечиваем их сохранение. Аналитика, оценки, графики и рейтинги — не в этой задаче.

---

## Принятые решения

### Хранение

- Скалярные показатели (вода, шаги, сон, активность, вес) хранятся в таблице `daily_reports` отдельными колонками.
- Пульс хранится в отдельной таблице `pulse_readings`, потому что замеров может быть несколько за день.
- Все новые поля **опциональны**. Пользователь заполняет то, что хочет.
- Отчёт сохраняется, если заполнено хотя бы одно из: еда, любая метрика, хотя бы один замер пульса.
- Если всё пустое — отчёт не сохраняем (или не создаём).

### Единицы измерения

| Показатель | Единица | Тип в БД |
|---|---|---|
| Вода | литры, целое число | `INTEGER` (`water_liters`) |
| Шаги | шаги, целое число | `INTEGER` (`steps`) |
| Сон | часы, целое число | `INTEGER` (`sleep_hours`) |
| Активность | минуты | `INTEGER` (`activity_minutes`) |
| Вес | кг, целое число | `INTEGER` (`weight_kg`) |
| Пульс | уд/мин, целое число | `INTEGER` (`pulse`) |

### Время замера пульса

- В интерфейсе подставляется текущее время, но пользователь может его изменить.
- Дата замера определяется отчётным днём (`stream.start_date + day_number`).
- В БД хранится как `TIMESTAMP WITH TIME ZONE`: дата отчётного дня + указанное время, конвертированные из таймзоны пользователя в UTC.

## Шаг 1. База данных

### 1.1. Миграция для `daily_reports`

Создать миграцию, которая добавляет в `daily_reports` колонки:

- `water_liters` — `INTEGER`, nullable, default `NULL`
- `steps` — `INTEGER`, nullable, default `NULL`
- `sleep_hours` — `INTEGER`, nullable, default `NULL`
- `activity_minutes` — `INTEGER`, nullable, default `NULL`
- `weight_kg` — `INTEGER`, nullable, default `NULL`

### 1.2. Миграция для `pulse_readings`

Создать таблицу `pulse_readings`:

- `id` — UUID, PK
- `report_id` — UUID, FK → `daily_reports(id)`, `ON DELETE CASCADE`
- `measured_at` — `TIMESTAMP WITH TIME ZONE`, not null
- `pulse` — `INTEGER`, not null
- индекс по `report_id`

### 1.3. Обновить модели Sequelize

- В `DB/models/DailyReport.ts` добавить поля:
  - `waterLiters`
  - `steps`
  - `sleepHours`
  - `activityMinutes`
  - `weightKg`
- Создать `DB/models/PulseReading.ts` с полями:
  - `id`
  - `reportId`
  - `measuredAt`
  - `pulse`
- Настроить связь: `DailyReport.hasMany(PulseReading)`, `PulseReading.belongsTo(DailyReport)`.
- Обновить `DB/db.ts` (или где регистрируются модели), чтобы включить `PulseReading`.

## Шаг 3. API

### 3.1. `POST /api/streams/[id]/day/[dayNumber].ts`

- Принимать расширенное тело запроса.
- Создавать или находить `DailyReport`.
- Сохранять скалярные метрики.
- Для пульса: удалять старые записи `PulseReading` за этот отчёт и создавать новые.
- Пересчитывать `totalCalories` по строкам еды (если есть).

### 3.2. `PUT /api/reports/[reportId].ts`

- Аналогично POST: сохранять метрики и замены пульса.
- Пересчитывать калории.

### 3.3. `GET /api/streams/[id]/day/[dayNumber].ts`

- Возвращать отчёт с метриками и списком замеров пульса.
- Упорядочить замеры пульса по `measured_at`.

### 3.4. Зависимые эндпоинты (проверить)

- `/api/streams/[id]/calendar.ts` — убедиться, что наличие отчёта без еды всё ещё считается заполненным днём.
- `/api/streams/[id]/results.ts` — пока не добавлять новые данные в ответ, но убедиться, что структура не сломалась.

## Шаг 6. Проверка

### 6.1. Ручное тестирование

- Создать отчёт только с едой — работает как раньше.
- Создать отчёт только с водой/шагами/весом — сохраняется.
- Создать отчёт только с пульсом — сохраняется.
- Создать отчёт с несколькими замерами пульса — сохраняются и отображаются.
- Открыть существующий отчёт — данные подгружаются корректно.
- Попытаться сохранить пустой отчёт — ошибка.

### 6.2. Проверить миграции

- `npx sequelize-cli db:migrate` отрабатывает без ошибок.
- `npx sequelize-cli db:migrate:undo` откатывает изменения.

### 6.3. Проверить типизацию

- `npm run build` или `npm run type-check` проходит без ошибок.
