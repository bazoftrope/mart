# Концепция стиля (дизайн-система)

Единый источник правды по визуальному языку платформы. Всё, что описано здесь, лежит в токенах
`src/styles/globals.css`. Новые цвета и размеры в компонентах берём только через токены.

Референс, с которого снята концепция: `public/concept_v2.jpg` (стилегайд-плакат в стиле клейморфизма).
Предыдущая концепция (приглушённый зелёный + кремовый + терракота) снята с `DOC/local/refs/concept.jpg`
и заменена — см. `DOC/decisions-log.md`, Решение 26.

---

## 1. Направление

**Тактильно, спокойно, дружелюбно, аккуратно.** Молочные нейтрали как основа, графитовый текст,
один мятный акцент. Элементы выглядят как объёмные, но мягкие объекты: свет падает слева сверху,
поэтому у «поднятых» поверхностей сверху светлая кромка, а снизу — диффузная тень; поля ввода,
наоборот, «вдавлены» в поверхность. Рамок почти нет: поверхности разделяются тенью и заливкой.

Аудитория — участники марафонов по снижению веса, в основном заполняют отчёты с телефона. Отсюда
требования: высокая читаемость мелкого текста, крупные тап-зоны, спокойные пастельные цвета
без «кислотности».

Из референса сознательно **не переносится**: 3D-рендер плаката, миллиметровая сетка и линейки,
тема биллинга/B2B-SaaS, полностью «объёмные» (level 4–5) тени на плотных экранах отчётов.

**Клейморфизм дозирован.** Полный объём оставлен для посадочных поверхностей (карточки, кнопки,
панели). В таблицах отчётов и формах дня используем только мягкую тень и заливку, чтобы данные
оставались максимально читаемыми.

## 2. Палитра

Логика: молочные нейтрали + графит + **один** мятный акцент. Мята светлая, поэтому у неё две роли:
заливка под тёмный текст (`--accent-primary` + `--text-on-accent`) и «сильный» вариант для текста,
ссылок и иконок (`--accent-strong`).

### Правила контраста (жёсткие)

Проверено расчётом WCAG AA — **все пары ниже проходят порог 4.5:1** (и 3:1 для элементов интерфейса):

1. **Светлая мята не держит белый текст.** На `--accent-primary`, `--bg-panel-hero-*` и всех светлых
   заливках текст только тёмный: `--text-on-accent` или `--text-on-sage`. Белый текст допустим только
   на тёмных заливках: `--bg-panel-deep`, `--accent-success`, `--text-danger`.
2. **`--accent-primary` запрещено использовать как цвет текста, ссылки, иконки или индикатора** —
   для этого есть `--accent-strong`. Мята на белом даёт 1.4:1.
3. `--accent-decor` (`#6FDCC0`) **никогда не фон под текст**: только графика и крупные акценты.
4. `--text-muted-extra` не используем для текста мельче 14px.
5. Интерактив без текстовой метки (иконка-кнопка, индикатор вкладки) — не менее 3:1 к фону.
   Кольцо фокуса `--focus-ring-color` (`#1F7A63`) видно и на молочном фоне, и на мятной кнопке.

Перепроверить пары расчётом можно так. Кладём во временный файл `contrast.cjs` в корне проекта
(в репозиторий не коммитим) и запускаем `node contrast.cjs`:

```js
// contrast.cjs — проверка пар «текст/фон» из этого документа
const fs = require("fs");
const css = fs.readFileSync("src/styles/globals.css", "utf8");
const root = css.slice(css.indexOf(":root {"), css.indexOf("}", css.indexOf(":root {")));
const tok = {};
for (const m of root.matchAll(/(--[a-z0-9-]+):\s*(#[0-9a-fA-F]{3,6})\s*;/g)) tok[m[1]] = m[2];

const lum = (h) => {
  const c = h.replace("#", "").match(/../g)
    .map((x) => parseInt(x, 16) / 255)
    .map((v) => (v <= 0.03928 ? v / 12.92 : Math.pow((v + 0.055) / 1.055, 2.4)));
  return 0.2126 * c[0] + 0.7152 * c[1] + 0.0722 * c[2];
};
const ratio = (a, b) => {
  const [hi, lo] = [lum(a), lum(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
};

const pairs = [
  ["Основной текст на фоне страницы", "--text-secondary", "--bg-body", 4.5],
  ["Основной текст на поверхности", "--text-secondary", "--bg-surface", 4.5],
  ["Приглушённый текст на серой подложке", "--text-muted-extra", "--bg-surface-muted", 4.5],
  ["Плейсхолдер на вдавленном поле", "--text-placeholder", "--bg-surface-muted", 4.5],
  ["Тёмный текст на мятной кнопке", "--text-on-accent", "--accent-primary", 4.5],
  ["Текст в херо на тёмной части мяты", "--text-on-sage", "--bg-panel-hero-end", 4.5],
  ["Кремовый текст на глубокой панели", "--text-on-deep", "--bg-panel-deep", 4.5],
  ["Ссылка на поверхности", "--text-link", "--bg-surface", 4.5],
  ["Успех на мягкой мяте", "--text-success", "--bg-success", 4.5],
  ["Ошибка на пастельно-розовом", "--text-danger", "--bg-danger", 4.5],
  ["Белый текст на зелёной кнопке", "--text-on-dark", "--accent-success", 4.5],
  ["Кольцо фокуса на мятной кнопке", "--focus-ring-color", "--accent-primary", 3],
];

let failed = 0;
for (const [name, fg, bg, threshold] of pairs) {
  const r = ratio(tok[fg], tok[bg]);
  if (r < threshold) failed++;
  console.log(`${r >= threshold ? "OK  " : "FAIL"} ${r.toFixed(2)}  ${name}`);
}
process.exit(failed ? 1 : 0);
```

Текущий прогон по полному списку пар (36 пар, включая состояния кнопок, бейджи ролей и
семантические поверхности): **все проходят**. Самые узкие места — плейсхолдер на серой подложке
(4.69), кольцо фокуса на мятной кнопке (3.82, порог для интерфейса 3:1), приглушённый текст
на молочном (5.17). Если меняете эти токены — перепроверяйте.

## 3. Типографика

Шрифт — **Golos Text** (подключается через `next/font/google` в `src/pages/_app.tsx`, переменная `--font-golos`).
Оставлен из предыдущей концепции сознательно: он сделан под кириллицу и хорошо читается в мелких
таблицах отчётов. Геометрический гротеск из референса (Inter/SF Pro) на UI-размерах отличается
незначительно, а смена шрифта меняет метрики и ломает вёрстку — отдельное решение, не часть этого прохода.

| Роль | Токен | Значение |
| :--- | :--- | :--- |
| Заголовок херо | — (в `index.module.css`) | 2.5rem / 800 |
| Заголовок страницы | `--font-size-2xl` | 1.4rem / 800 |
| Заголовок секции | `--font-size-xl` | 1.25rem / 700 |
| Основной текст | `--font-size-regular` | 1rem / 400 |
| Мелкий текст, подписи | `--font-size-sm` / `--font-size-xs` | 0.8rem / 0.75rem |

Начертания: `--font-weight-normal` 400, `medium` 500, `semibold` 600, `bold` 700, `extrabold` 800.

**Правила:**
- **Sentence case везде, регистр не форсируем.** `text-transform: uppercase` и `lowercase` в новых стилях
  не используем — иерархия набирается размером и весом. В этом проходе капс убран из `ReportTable`,
  `CalorieSummary` (подписи и заголовки блоков) и `DayTabs`.
- Межстрочный: `--line-height-tight` 1.25 для заголовков, `--line-height-normal` 1.6 для текста.
- Заголовки — трекинг `--letter-spacing-tight` (−0.01em).
- Микро-подписи в карточках итогов не «глушим» прозрачностью: прозрачность уводит контраст ниже 4.5:1,
  вместо неё — цвет `--text-muted-extra`.

### Шкала теней (клейморфизм)

Мягкие диффузные тени с нейтральным графитовым подтоном, свет — слева сверху.

| Токен | Назначение |
| :--- | :--- |
| `--elevation-1` … `--elevation-5` | шкала Elevation из концепта, от едва заметной до глубокой |
| `--shadow-sm` / `--shadow-md` / `--shadow-float` | алиасы `elevation-2/3/4` для совместимости |
| `--shadow-clay-sm` / `--shadow-clay` | «поднятый» элемент: светлая кромка сверху + тень снизу (карточки, кнопки, чипы) |
| `--shadow-inset` | «вдавленная» поверхность: поля, ячейки ввода, нажатая кнопка |
| `--focus-ring` | мятное свечение вокруг кольца фокуса |

Рамки — исключение, а не норма: вместо них заливка поверхности, тень и хейрлайн `--border-default`.
Кнопки при нажатии «проваливаются» (`--shadow-inset` + сдвиг на 1px), это часть языка клейморфизма.

Отступы — шаг 4px через токены `--space-*`. Секции лендинга разделяются крупными вертикальными отступами.

**Брейкпоинты (три, других не заводим):**
- `≤640px` — мобильный,
- `641–900px` — планшет; на `≤900px` хедер сворачивается в бургер,
- `>900px` — десктоп.

## 5. Компоненты и состояния

У каждого интерактивного элемента обязательны состояния: `default`, `hover`, `focus-visible`, `disabled`,
а у полей ещё `error`.

**Кнопки.** Primary — мятная пилюля (`--accent-primary`) с тёмным текстом `--text-on-accent` и
«клей»-тенью; при нажатии — `--shadow-inset` и сдвиг вниз. Secondary — белая заливка, тёмный текст
(для размещения на мятных панелях). Tertiary — заливка `--bg-panel-deep`, кремовый текст.
Disabled — серая заливка `--bg-surface-disabled` без тени. Глобальные классы: `.btn`, `.btnPrimary`,
`.btnOutline`, `.btnSuccess`, `.btnDanger` в `globals.css`.

**Поля ввода.** Пилюля, «вдавленная» заливка `--shadow-inset` без рамки; при фокусе — кольцо `3px`
цвета `--focus-ring-color` с мятным свечением `--focus-ring`. Глобальный класс `.input`.
Числовые поля в отчёте дня следуют тому же языку (пилюля + inset).

**Фокус.** Глобальное правило `:focus-visible` в `globals.css` даёт видимое кольцо всем элементам.
Светлую мяту в `outline` не ставим — используем `--focus-ring-color`.

**Бейджи и чипы.** Пилюли. Нейтральные — `--bg-surface-secondary` + `--text-secondary`; выбранные —
мятная заливка `--accent-primary` + `--text-on-accent`; статусные — пары `--bg-*` / `--text-*`
(успех, предупреждение, ошибка, информация). Примеры: бейджи дня (`DayHeader`), чипы приёмов пищи
(`DayReport`), выбор цели в потоке.

**Табы.** Два варианта: подчёркнутые (`DayTabs`, активный — индикатор `--accent-strong`) и
пилюльные чипы (`DayReport.mealTab`). Капс в шапке таблицы отчёта убран.

**Плитки дней марафона** (`Marathon.module.css`, календарь дней на главной участника). Плитка —
«поднятая» поверхность со скруглением `--radius-md` и тенью `--shadow-clay-sm`; состояние наведения —
`--shadow-clay`. Состояния по заливке: доступный день — `--bg-surface`, недоступный (будущий) —
`--bg-surface-disabled` без тени, день с отчётом — `--bg-success`, перебор калорий — `--bg-danger`.
Выбранный день — мятная заливка `--accent-primary` с текстом `--text-on-accent` и масштабом `1.1`;
статус дня на нём читается цветом числа калорий (`--text-success` / `--text-danger`, проверено 4.71 и
4.65 на мяте). Текущий день (сегодня) помечает индикатор `--accent-strong` по кромке плитки: светлая
мята как индикатор не читается (1.4:1). Рамка под индикатор зарезервирована прозрачной у всех плиток,
поэтому геометрия дней не «дрожит». Ту же роль в легендах дней несут бейджи `DayHeader`.

**Таблицы.** Шапка — нейтральный градиент `--bg-surface` → `--bg-surface-muted` с мягкой тенью
`--elevation-2` на `th::after`, подписи `--text-secondary`, капс не используем. Тело: хейрлайн-
разделители, подсветка строки при наведении фоном `--bg-surface-muted`, без зебры. Поля ввода в
ячейках — пилюля с `--shadow-inset`. Горизонтальный скролл внутри контейнера на мобильном.

В `ReportTable.module.css` остались неподключённые классы `.headerOk` / `.headerOver` (мятная и
розовая шапка по состоянию калорий) — в разметке применяется только `.headerRow`. Это задел, а не
работающее поведение; если решите не использовать — удаляйте вместе с селекторами `.headerOk ~ tbody …`.

**Иконки.** Набор — `src/components/icons/index.tsx`. Монохромные части рисуем `currentColor`
(иконка наследует цвет текста: в бейджах берёт их семантический токен, у кнопок — цвет кнопки),
акцентные заливки — токенами (`--accent-primary` для корпуса весов и крема пироженки, `--accent-decor`
для тени крема), белые детали (циферблат, блик) — `--bg-surface`. Литеральные hex не хардкодим.
`viewBox` у всех иконок, кроме `diet_food`, нормализован так, чтобы глиф занимал ~0.85 коробки — иначе
в одном ряду иконки одного размера выглядят разновеликими. `diet_food` — многоцветная иллюстрация:
её артворк, цвета и `viewBox` не трогаем, и она всегда идёт первым ключом в наборе.

## 6. Мобильный

Основной сценарий участника — отчёт по питанию с телефона, поэтому мобильный вид обязателен.

- Одна колонка, кнопки в `<main>` на всю ширину.
- Хедер на `≤900px` — бургер (`Menu`/`X` из `lucide-react`), панель меню под шапкой, закрытие по клику
  на ссылку и по `Esc`.
- Тап-зоны не меньше 44px.
- Таблицы — горизонтальный скролл внутри контейнера, а не выезд за пределы страницы.
- Горизонтального скролла страницы нет ни на 360px, ни на 320px.

  `CalorieSummary`, `MetricBlock`, `DayPulse`, `ProductSearch`, `PulseReadingsForm` — литеральные
  цвета заменены токенами, капс убран, поля «вдавлены»;
- цвета графиков в `DayPulse` и `CalorieSummary` переведены на `var(--chart-*)`;
- календарь дней марафона (`components/marathon/*`): шапка окна, навбар дней и плитки дней
  (`MarathonHeader`, `DayNavbar`, `DayNavbarButton`, `MarathonWindow`) — в `Marathon.module.css`
  литеральных цветов не осталось (Решение 30).

**Не переведено (берёт новые значения токенов, но носит собственные литеральные цвета):**
- админ-разделы (`pages/admin/*`) — включая инлайновые цвета статусов в `admin/users`;
- чат, редактор, вложения, книги рецептов и тренировок, помощь — кроме тех мест, где пришлось
  починить контраст (см. ниже);
- `pages/dashboard/*` и `pages/mentor/*` — кроме календаря дней марафона и карточки потока;
- вкладка «Прогресс» марафона (`MarathonProgress.module.css`: плашка «Мой прогресс», подписи, графики
  калорий и веса) и графики на `pages/dashboard/.../results`, `pages/mentor/.../[participantId]` —
  по-прежнему на литеральных blue/green/orange, читаемы, но выбиваются из палитры.

**Починено по ходу смены акцента (иначе было бы нечитаемо).** Светлая мята вместо терракоты сломала бы
все места, где акцент использовался как цвет текста, иконки или индикатора — там теперь
`--accent-strong`; белый текст на акцентных заливках заменён на `--text-on-accent`; мятные `outline`
при фокусе заменены на `--focus-ring-color`. Затронуты: чат (`Chat`, `MarathonChatPopup`,
`MentorStreamChat`), вложения (`AttachmentPairCards`, `AttachmentPlayers`, `ContentAttachmentManager`),
карточки рецептов/тренировок/статей, `pages/{recipes,workouts,help}/*`, `pages/admin/help`.

**Известный технический долг.** В `globals.css` остались помеченные как deprecated дубли
`--bg-fon`, `--bg-fon1`, `--bg-surface-tertiary`, `--bg-surface-disabled` и алиасы совместимости
(`--color-primary`, `--color-accent`, `--bg-muted`, `--border-soft`, `--accent-danger`) — при правках
компонентов их лучше заменять на основные токены. В модулях вне периметра прохода всё ещё есть
литеральные hex-цвета; постепенно заменяем их токенами.

## 8. Как расширять систему

1. Новый цвет/размер сначала появляется токеном в `:root` (`globals.css`) — с комментарием, зачем он нужен.
2. Если токен нужен только одному компоненту — объявляем его локально в CSS-модуле этого компонента.
3. Новую пару «текст/фон» проверяем на контраст ≥4.5:1 (а для элементов интерфейса ≥3:1) и добавляем
   в таблицу раздела 2.
4. Литеральные hex в CSS-модулях и inline-стилях не хардкодим. Данные графиков — исключение только по
   форме записи: цвет всё равно берём из токена `--chart-*`.
5. Фреймворки стилей (Tailwind, styled-components) не добавляем — у нас CSS Modules + токены.
