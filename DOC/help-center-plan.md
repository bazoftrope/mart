# Раздел «Правила и помощь» (`/help`)

Статус: **реализовано** (11.09.2026). Вариант A из обсуждения — контент в БД,
редактирование из админки, публичное чтение.

## Зачем

Пользователю нужны правила марафона и ответы на частые вопросы: что заполнять
каждый день, где дни замеров, как считается рейтинг, как записаться, как
запустить марафон ментору. Раздел открыт всем, включая гостей, и обновляется
админом без деплоя.

## Модель данных

Таблица `help_articles` (модель `DB/models/HelpArticle.ts`):

| Поле | Тип | Назначение |
|------|-----|-----------|
| `id` | UUID PK | |
| `slug` | string, unique | Адрес статьи: `/help/<slug>` |
| `title` | string | Заголовок |
| `summary` | text, null | Краткое описание для карточки и поиска |
| `content` | text | HTML из Quill (санируется на сервере) |
| `section` | enum `rules`/`faq`/`guide` | Раздел |
| `audience` | enum `all`/`participant`/`mentor`/`admin` | Для кого |
| `position` | integer | Порядок вывода внутри раздела |
| `isPublished` | boolean | Черновик / опубликовано |
| `createdBy` | UUID, null → User.id, SET NULL | Служебное, в UI не показывается |
| `createdAt` / `updatedAt` | datetime | |

Миграция: `DB/migrations/20260911000001-create-help-articles.js`.
Стартовый набор из 7 статей: `DB/seeders/20260911000001-demo-help-articles.js`.

## API (`src/pages/api/help/`)

| Метод | Роут | Доступ |
|-------|------|--------|
| `GET` | `/api/help?search=&section=&audience=` | публично (`withOptionalAuth`) |
| `POST` | `/api/help` | админ |
| `GET` | `/api/help/[slug]` | публично; черновик — только админ |
| `PUT` | `/api/help/[slug]` | админ (можно менять `slug`) |
| `DELETE` | `/api/help/[slug]` | админ |

Правила видимости:
- гость — только `isPublished = true` и `audience = all`;
- участник — плюс `audience = participant`, ментор — плюс `audience = mentor`;
- админ — всё; `GET /api/help?all=1` отдаёт черновики и все аудитории (для `/admin/help`).

Валидация — `helpArticleSchema` в `src/lib/validate.ts` (slug: `^[a-z0-9]+(?:-[a-z0-9]+)*$`),
контент санируется `sanitizeRichText` (`src/lib/sanitize.ts`) при создании и изменении.

  Инструкции / Частые вопросы», карточки, пустое состояние. Для админа — кнопка
  «Управление разделом».
- `src/pages/help/[slug].tsx` — статья: бейджи, санированный HTML, дата

- `src/pages/admin/help/index.tsx` — таблица статей (включая черновики), добавить /

Контекстные ссылки:
- день марафона, блок «Отчёт» → «Как заполнить отчёт?» (`DayReport.tsx`);

- форма регистрации → «правилами марафона» (`register.tsx`).

## Как добавить или изменить статью

1. Войти админом.
2. Открыть `/admin/help` (или ссылку «Статьи помощи» в шапке).
3. «Добавить статью» либо «Изменить».
4. Заполнить заголовок — адрес (slug) подставится автоматически; при
   необходимости поправить вручную.
5. Выбрать раздел, аудиторию и порядок; написать текст в редакторе.
6. Оставить галочку «Опубликовать» или снять её для черновика.
7. Сохранить.

Удаление статьи необратимо и требует подтверждения. Статьи из сидера ничьи —
их может править только админ.

## Принятые решения и ограничения

- **Только админ редактирует контент.** Роль вводится, чтобы не плодить права
  автора/админа, как в книгах рецептов.
- **Слаги — часть интерфейса.** `src/lib/helpSlug.ts` экспортирует
  `HELP_SLUG_RULES` (`pravila-marafona`) и `HELP_SLUG_REPORT_GUIDE`
  (`kak-zapolnyat-otchet`), на которые ссылаются страница дня, поток и
  регистрация. Если переименовать или удалить эти статьи, соответствующие ссылки
  начнут вести на 404 — при переименовании обновите константы в коде.
- **Регистрация не блокируется правилами.** Согласие оформлено текстовой
  ссылкой, отдельного чекбокса и хранения согласия нет (в MVP не требуется).
- **`dangerouslySetInnerHTML`** используется так же, как для текстов дня и
  предстартовой страницы: HTML уже санирован на сервере при сохранении.

## Как накатить

```bash
npx sequelize-cli db:migrate

```
